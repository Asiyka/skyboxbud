# Заглушка — лендінг

React + Vite, один основний компонент `src/App.jsx`. Проєкт готовий до продакшн-деплою:
локальні зображення (без хотлінка на Unsplash), SEO-теги, favicon, кешування статики.

## Перед першим деплоєм — обов'язково

Усі бізнес-дані винесені в один блок на початку `src/App.jsx`:

```js
const PHONE_HREF = "tel:+380000000000";       // ← реальний номер, формат tel:+380XXXXXXXXX
const PHONE_TEXT = "+38 (000) 000-00-00";      // ← той самий номер у зручному для читання вигляді
const COMPANY_NAME = "Заглушка";               // ← назва компанії
const COMPANY_ADDRESS = "м. Місто, вул. Прикладна, 1"; // ← реальна адреса
const PRODUCTION_AREA = "[м²]";                // ← площа виробництва, напр. "2 400 м²"
```

Замінити всі п'ять значень — і в `index.html`:
- `<title>`, `description`, `og:*`, `twitter:*` — якщо назва компанії інша, ніж «Заглушка»
- рядки з `ваш-домен.com` (4 місця) — на реальний домен, коли він буде

І в `public/robots.txt` / `public/sitemap.xml` — та сама заміна `ваш-домен.com`.

Також вирішити спосіб зв'язку — на початку файлу:

```js
const DEFAULT_VARIANT = { contact: "form" }; // або "phone" — без форми, лише номер
```

`SHOW_SWITCHER` вже виставлено в `false` (плаваючий перемикач для показу клієнту вимкнено).

## Крок 0 — реальні фото (обов'язково для продакшну)

Пісочниця, в якій готувався код, не має доступу до фотохостингів, тому зображення
поки що не завантажені. У вас — повний доступ в інтернет, тому одна команда:

```bash
npm install
npm run fetch:images
```

Скрипт `scripts/fetch-images.mjs` завантажить 5 фото з Unsplash (Unsplash License —
вільне комерційне використання) у `public/images/`. Далі закомітити їх разом з кодом:

```bash
git add public/images
git commit -m "Додати реальні фото"
```

Так фото стають частиною репозиторію — сайт більше не залежить від Unsplash і не
зламається, якщо там щось зміниться. Якщо є власні фото виробництва — просто
покладіть їх у `public/images/` під тими самими іменами:

```
warehouse.jpg       — фото в шапці (широке, 21:9)
small-crates.jpg    — малі ящики
medium-crates.jpg   — середні ящики
large-crates.jpg    — великі ящики
custom-crates.jpg   — під замовлення
```

## Галерея фото в каталозі

Кнопка «Фото · N» на фото кожного формату відкриває галерею. Набір фото для кожного
формату — масив `PRODUCT_GALLERIES` на початку `src/App.jsx` (зараз там тимчасово ті самі
5 фото в різному порядку). Додати свої: покласти `.jpg` у `public/images/` і вписати
імена файлів (без `.jpg`) у потрібний рядок масиву. Перше фото — обкладинка слайда.

## Деплой: GitHub + Vercel

### 1. GitHub

```bash
cd skyboxbud
git init
git add .
git commit -m "Перший коміт: лендінг"
```

На github.com: **New repository** → назва (напр. `skyboxbud`) → **Create repository**,
без README/gitignore на цьому кроці. Далі виконати команди, які покаже GitHub:

```bash
git remote add origin https://github.com/ВАШ_НІК/skyboxbud.git
git branch -M main
git push -u origin main
```

### 2. Vercel

1. **vercel.com** → Sign up через GitHub
2. **Add New… → Project** → обрати `skyboxbud` → **Import**
3. Framework Preset визначиться сам як **Vite** — нічого не змінювати
4. **Deploy**

Через хвилину-дві отримаєте безкоштовний домен:

```
https://skyboxbud-xxxx.vercel.app
```

Кожен `git push` у `main` автоматично оновлює сайт.

### 3. Свій домен пізніше

Vercel → проєкт → **Settings → Domains** → ввести домен → **Add**. Vercel покаже
DNS-записи (A/CNAME) — додати їх у панелі реєстратора домену. SSL-сертифікат
Vercel випустить сам. Безкоштовний `.vercel.app` продовжує працювати паралельно.

Після підключення домену не забути оновити `ваш-домен.com` у `index.html`,
`robots.txt` і `sitemap.xml` на реальний і задеплоїти ще раз.

## Заявки в Telegram

Форма шле заявку на `/api/lead`, а бот публікує її у ваш закритий канал. Токен бота
живе лише на сервері. Валідація: ім'я обов'язкове + телефон **або** email.
Без баз даних: стан заявки живе в самому повідомленні, а список нагадувань — у
закріпленому повідомленні каналу.

### Що вміє бот у каналі
- **Статуси** — кнопки під заявкою: ✅ Передзвонили · 📵 Не взяли трубку · 🤝 Замовлення ·
  ❌ Відмова; «⏰ Пізніше» ставиться з міні-застосунку (див. «Нагадування»). Перший рядок заявки показує поточний статус, внизу — історія
  (хто й коли змінив). Працювати можуть лише адміністратори каналу.
- **Фільтри** — хештеги в кожній заявці: `#відкрита` (нова, не взяли, пізніше),
  `#вроботі` (передзвонили), `#закрита` (замовлення, відмова), а також `#нова`,
  `#недодзвонились`, `#пізніше`, `#передзвонили`, `#замовлення`, `#відмова`, `#нотатки`.
  Тап по хештегу — усі такі заявки. Список фільтрів закріплений угорі каналу.
- **Нотатки** — «📝 Нотатка» під заявкою → бот пише «✍️ [ваше ім'я], напишіть нотатку…» →
  ви пишете текст звичайним повідомленням у канал → бот додає його в заявку з вашим
  ім'ям, каже «Дякую» і прибирає і питання, і відповідь.
- **Нагадування** — посилання «⏰ Нагадати: t.me/…» у тексті кожної заявки відкриває
  міні-застосунок «Дата й час» прямо в Telegram (саме посилання, а не кнопка: кнопку Telegram
  щоразу просить підтвердити, а видиме посилання — лише першого разу):
  крок 1 — день (швидкі вибори «Завтра / Через тиждень / …» або календар), крок 2 — час
  (колесо годин і хвилин). Найраніше — наступна хвилина (о 00:12 можна поставити 00:13).
  Там же — «Позначити «Пізніше» без нагадування». Усі заплановані нагадування видно
  в закріпленому повідомленні (блок «⏰ Найближчі нагадування», рядок веде на заявку).
  У потрібний час бот надішле в канал «🔔 Нагадування: передзвонити» з цитатою заявки;
  якщо статус змінили раніше — нагадування знімається саме. Максимум — 100 запланованих
  нагадувань одночасно (стільки вміщає закріплене повідомлення).

### Права бота в каналі
Канал → Адміністратори → бот: **Публікація повідомлень**, **Редагування повідомлень інших**
(закріплене повідомлення зі списком нагадувань) і **Видалення повідомлень інших**
(щоб прибирати ваші відповіді на запити бота).

### 1. Бот і канал (вже зроблено)
1. **@BotFather** → `/newbot` → токен → `TELEGRAM_BOT_TOKEN`.
2. Приватний канал, бот — адміністратор (права — вище).
3. `TELEGRAM_CHAT_ID` — id каналу (`-100…`), `TELEGRAM_WEBHOOK_SECRET` — довгий випадковий рядок.
   Усі три вже лежать у `.env.local`.

### 2. Локально — ⚠️ не забути про вебхук

Бот працює **або** на продакшні (вебхук → `https://skyboxbud.vercel.app/api/telegram`),
**або** на вашому компʼютері — одночасно не можна, Telegram віддає оновлення комусь одному.

| Що робимо | Команда |
|---|---|
| Сайт локально (форма шле заявки в той самий канал) | `npm run dev` |
| Бот локально: кнопки, нотатки, нагадування + тестова «⚡ 1 хв» | `npm run tg:local` (у другому терміналі) |
| Повернути бота на продакшн | **Ctrl+C** у вікні `tg:local` — повертає вебхук сам (навіть якщо минулий запуск обірвався) |
| Якщо закрили термінал хрестиком / впав компʼютер | `npm run tg:prod` — обовʼязково! |
| Перевірити, де зараз бот | `npm run tg:webhook -- info` (порожній `url` = локально) |

Поки працює `tg:local`, кнопки під заявками на **продакшні теж** обробляє ваш компʼютер:
вимкнули його без Ctrl+C — кнопки в каналі мовчать, доки не виконати `npm run tg:prod`.

**Міні-застосунок «Дата й час»** локально в Telegram не відкривається (Telegram бачить лише
https-адресу продакшну). Верстку зручно крутити в браузері:
`http://localhost:5173/tg-remind.html?startapp=1_0J7Qu9C10L3QsA` (покаже «Нагадати: Олена»).
Щоб побачити зміни в самому Telegram — запушити (адреса в @BotFather веде на продакшн).

### 3. Деплой на Vercel — покроково
**Крок 1. Код на GitHub.** `git push` у гілку `main` (репозиторій `asiyka/skyboxbud`).

**Крок 2. Проєкт у Vercel** (якщо ще не створений). vercel.com → **Add New… → Project** →
обрати `skyboxbud` → **Import**. Framework визначиться як **Vite** — нічого не міняти.
Поки не тиснути Deploy, спершу — змінні (крок 3). Якщо проєкт уже є — одразу до кроку 3.

**Крок 3. Змінні.** Проєкт → **Settings → Environment Variables**, для **Production** і
**Preview** додати (значення — з `.env.local`):

| Назва | Значення |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `TELEGRAM_CHAT_ID` | id каналу `-100…` |
| `TELEGRAM_WEBHOOK_SECRET` | секрет |

**Крок 4. Деплой.** **Deployments → ⋯ → Redeploy** (або **Deploy** для нового проєкту).
Запамʼятати адресу сайту, напр. `https://skyboxbud.vercel.app`. Перевірити: сайт відкривається,
`https://…/tg-remind.html` показує календар.

**Крок 5. Міні-застосунок у @BotFather.** `/mybots` → бот → **Bot Settings** →
**Configure Mini App** → **Enable Mini App** → надіслати адресу
`https://skyboxbud.vercel.app/tg-remind.html`.
*Якщо такого пункту немає:* `/newapp` → бот → назва, опис, будь-яке фото 640×360 → URL як вище
→ короткe імʼя, напр. `remind`; тоді у Vercel додати ще `TELEGRAM_APP_NAME=remind` і Redeploy.

**Крок 6. Вебхук** (один раз; спершу зупинити `npm run tg:local`, якщо запущений):
`npm run tg:prod` → має бути «✓ Вебхук підключено». ✅ Зроблено.
Повторювати лише при зміні домену, токена чи секрету — не після кожного деплою.

**Крок 7. «Будильник» для нагадувань** — **cron-job.org** (безкоштовно): зареєструватися →
**Create cronjob** → URL `https://skyboxbud.vercel.app/api/cron?key=ВАШ_TELEGRAM_WEBHOOK_SECRET`
→ розклад **Every minute** (щохвилини) → **Create**. Перевірити: цей URL у браузері показує
`{"ok":true,…}`.

Чому щохвилини: нагадування надсилає саме цей «будильник». Раз на 5 хв — нагадування на
22:48 прийшло б о 22:50; щохвилини — о 22:48.

**cron-job.org чи Upstash QStash — і що буде, коли бізнес виросте.**
- cron-job.org — один виклик на хвилину незалежно від кількості заявок, тож навантаження
  й вартість не ростуть разом із бізнесом. Сервіс безкоштовний.
- QStash — окремий таймер на кожне нагадування (точність до секунди), безкоштовний ліміт,
  далі — оплата за кількість повідомлень, тобто росте разом із кількістю нагадувань.
- Коли перейдете на платний Vercel Pro — там є вбудований Cron (щохвилини), тоді
  cron-job.org можна прибрати: додати у `vercel.json` блок
  `"crons": [{ "path": "/api/cron", "schedule": "* * * * *" }]` і змінну `CRON_SECRET`
  (Vercel сам підписує виклик; код `/api/cron` це вже розуміє). На безкоштовному Vercel
  так не можна — там Cron лише раз на добу.
- Реальна межа росту — не будильник, а список у закріпленому повідомленні (до 100
  нагадувань одночасно). Якщо колись стане тісно — переносимо список у базу (напр.
  безкоштовний Upstash Redis), решта бота лишається як є.

**Крок 8. Перевірка.** Надіслати заявку з сайту → вона в каналі → «⏰ Пізніше» → «📅 Дата й
час» → обрати час через 5 хв → рядок у закріпленому → нагадування приходить у ту ж хвилину.

Далі кожен `git push` у `main` оновлює сайт сам; кроки 5–7 більше не потрібні.

Якщо ключів немає або Telegram недоступний, користувач побачить «Не вдалося надіслати
заявку…» з проханням зателефонувати — заявка не губиться мовчки.
